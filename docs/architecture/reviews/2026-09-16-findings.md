MERE CATHOLICITY — CODEBASE REVIEW: SUSTAINABILITY AND BEST PRACTICES
======================================================================
Date: 2026-09-16.  Tree: main @ 8d6df8c (the member model, forwarding and groups shipped).
Method: read-only. Every number below was measured from the checkout (wc, grep, git,
node:test output, npm audit) or read from production D1 as aggregates; file:line
references are to this tree. No code was changed. This file is untracked — per the root
rule in CLAUDE.md ("the root holds only tool-convention files") its home would be
docs/architecture/reviews/; see finding 11.

------------------------------------------------------------------------------
0. THE SHORT VERSION
------------------------------------------------------------------------------
The foundations are unusually good for a project this size: a pure PureScript kernel
behind one audited membrane, laws that each carry a test, a hermetic 8-second unit gate,
SHA-pinned CI with the push as the deploy, byte-deterministic builds, Terraform-declared
infrastructure, a migrations ledger, structured event logs, and real end-to-end
encryption designed with care. Keep all of that.

What threatens sustainability is not correctness but SHAPE and DUPLICATION, which raise
the cost of every change and are already visible in the week's work:

  • The test suite is mostly source-text locks (849 regex assertions over the worker and
    client sources; 36 of 52 JS/worker test files read source). They guard laws well and
    refactors badly — one feature this week rewrote ~20 locks, and a migration comment
    quoting "CHECK (kind IN (" tripped a lock. There is no harness that runs a worker
    handler against a real SQLite, so behaviour is pinned by string shape.
  • The worker is one 5,768-line file with 120 handlers and 272 inline SQL statements
    (+111 in lib.ts); CODEBASE.md still describes it as a "thin composition root
    (~150 lines)". A tracked plan for a repository layer (PLAN-TODO.md) was never done.
  • Two complete UIs are maintained: the classic client (client/*.ts, ~13k lines,
    dm.ts alone 3,165 with a 1,114-line viewDm) and the Lit views (app/views/*). The inbox
    exists twice, the profile twice; 13 delegation points. Every feature is built twice
    or the second copy lags (the Lit inbox got only a row label for groups).
  • `any` erases the strictness: 412 in index.ts, 378 in lib.ts, 428 in dm.ts; eslint
    enforces three rules. Wire shapes exist only as prose in API.md.
  • Nothing alerts. The daily D1 backup mirror had been silently absent for at least a
    week and was found by accident while shipping a table-swap migration.
  • Two agents work in one checkout; this week that pushed a migration to production a
    deploy ahead of the code that reads it (absorbed by a deliberate legacy index).

None of these is urgent in the sense of "the site is at risk today". All of them
compound. Section 2 ranks them with evidence and the smallest step that pays back.

------------------------------------------------------------------------------
1. WHAT IS STRONG — KEEP DOING IT
------------------------------------------------------------------------------
K1  The kernel/membrane split (purescript/src/Domain/*, app/core.ts) — shared rules exist
    once, both ends read them, the membrane erases Maybe/ADT in one audited place. The
    member-model work reused it end to end (Dm.membersEqual, readByAll, sys-line grammar).
K2  Laws that break silently each carry a test in the same change; the privacy sweep
    (tests/worker/dm_privacy.test.mjs) and the Turnstile-warm sweep
    (tests/js/turnstile_warm.test.mjs) are the right kind of lock: structural nets that
    catch a CLASS of bug, not one call site.
K3  The gate is hermetic and fast: 522 test() blocks across 84 files in ~7.7 s of node
    time (psbuild dominates the wall clock). Fast gates get run.
K4  CI is the build of record; every `uses:` SHA-pinned; secrets never on pull_request;
    Terraform plan fails on delete; the D1 ledger applies before the deploy; the worker
    job probes /config after deploying (workers.yml:193).
K5  Deterministic builds (SOURCE_DATE_EPOCH) and content-hashed ?v= keys — the double
    `make bundle` law is a real reproducibility guard.
K6  Media hygiene as a law with a sweep test; every delete road takes its object.
K7  The E2E design: static-static X25519 for pairs, now a per-message content key sealed
    per member for groups; the server stores only ciphertext, sealed keys and metadata;
    the reply quote and the Forwarded mark ride inside the plaintext; DMs never screened.
K8  Structured logs (`console.log(JSON.stringify({ event: … }))`, 89 sites) with Workers
    observability enabled (wrangler.jsonc:23) — the raw material for alerting exists.
K9  Documentation discipline: rules in CLAUDE.md, the why in INFRASTRUCTURE.md with
    dated lead-ins, an API contract, per-area READMEs. The habit is right; the shape
    has outgrown the files (finding 10, 12).
K10 npm audit: 0 vulnerabilities; one runtime dependency (lit); tooling exact-pinned
    where it matters (esbuild, purs, typescript); Dependabot bumps the CI pins.

2. FINDINGS, RANKED
------------------------------------------------------------------------------
Each: evidence → why it matters → the smallest step that pays back → rough effort.
P1 = compounds every week; P2 = velocity and quality; P3 = hygiene.

P1-1  Tests pin text, not behaviour
  Evidence: tests/worker 27 files — 19 read source, 15 run SQL on node:sqlite, 304 regex
  asserts; tests/js 25 files — 17 read source, 0 run code, 545 regex asserts. The idiom
  in tests/worker/dm_unread.test.mjs (`new Function('now', fragment('dmLive'))`) lifts SQL
  fragments out of lib.ts by regex because lib.ts cannot be imported in Node: its import
  graph reaches `cloudflare:` (the Durable Object). This week: ~20 lock rewrites for one
  feature; tests/purescript/notif.test.mjs greps the newest migration for
  "CHECK (kind IN (" and tripped on a comment that quoted the phrase.
  Why: refactoring cost scales with the number of locks, and a lock passing says the
  text is present, not that the road works; the pair-shape reaction bug shipped past
  522 green tests and was caught only by the prod fixture.
  Step: (a) make the worker's handlers executable in a test — the official road is
  @cloudflare/vitest-pool-workers (runs in workerd with a real D1); the cheap road is a
  50-line D1 shim over node:sqlite (prepare/bind/run/all/first/batch) plus moving the
  `cloudflare:` import behind an injected boundary so lib.ts loads in Node (I verified
  `import('./lib.ts')` fails today on ERR_UNSUPPORTED_ESM_URL_SCHEME). (b) Convert the
  highest-churn lock files first (dm_unread, dm_reactions, notif_read, media_hygiene,
  dm_actions, dm_chat_basics) into calls of the real handler with a seeded ledger.
  (c) Keep locks for laws that are genuinely textual (the privacy and Turnstile sweeps).
  Effort: shim + first two files ~1 day; the rest incremental, one file per feature touch.

P1-2  The worker is a monolith, and the map says otherwise
  Evidence: comments-worker/src/index.ts 5,768 lines, 120 `async function handle*`,
  272 `env.DB.prepare(` (lib.ts 111 more; db.ts holds 1 — the "repository layer" never
  arrived). Longest handlers: handleHandleCard 276 lines, handlePost 257, handleDmThread
  161, deliverDmWord 161, handleMerecatIngest 150. docs/architecture/CODEBASE.md:242,270
  describe index.ts as "a thin composition root (~150 lines)"; PLAN-TODO.md (tracked,
  root) planned "no inline prepare() in handlers" and was last touched 2026-09-09 for an
  unrelated retirement.
  Why: 120 handlers in one file means every agent edits the same file (merge risk with
  parallel work, P1-6), navigation by grep, and the preamble duplicated 80 times (P2-1).
  Step: split by feature behind the existing ROUTES table (index.ts:5545): dm.ts,
  calls.ts, board.ts, wall.ts, profile.ts, admin.ts, merecat.ts, notify.ts; move each
  handler verbatim (the Wave F method that split the client worked well); correct
  CODEBASE.md in the same change; mark PLAN-TODO.md superseded or execute it.
  Effort: ~2 days mechanical, tests moving with the handlers; zero behaviour change.

P1-3  Two UIs for the same screens
  Evidence: client/dm.ts viewInbox (1783) and app/views/profile.ts <mc-inbox>; client/
  profile.ts viewProfile and <mc-profile>; board/topic/post/admin likewise; 13
  `window.mcViews && window.mcViews.X` delegation points. Total client: comments.ts
  2,070 + dm.ts 3,165 + merecat.ts 1,924 + board.ts 1,733 + admin.ts 1,628 + composer.ts
  1,615 + profile.ts 1,455 + wall.ts 837 + surface.ts 621 ≈ 15k lines, ES5-style `var`
  inside TypeScript, viewDm 1,114 lines of nested closures.
  Why: this week the inbox needed two edits (classic + Lit) and the group features
  reached only the classic; the "no-bundle fallback" is a second product to test. The
  fixture webtest covers the classic path only.
  Step: decide which is the UI. The features land in the classic client, and the Lit
  views are thin; the least-loss cut is to retire the duplicated Lit views (inbox,
  profile) and let the shell host the classic views directly — or the reverse, but pick.
  Then split dm.ts into crypto.ts / thread.ts / inbox.ts / pickers.ts / styles.ts
  (install<Feature>(B) factories already exist; the seams are the function boundaries).
  Effort: decision 0; the split ~2 days; Lit retirement ~1 day.

P1-4  Strict mode is on and erased by `any`
  Evidence: `: any` — index.ts 412, lib.ts 378, dm.ts 428, comments.ts 180; tsconfig
  strict:true in both projects; eslint.config.js rules: no-undef, no-dupe-keys,
  no-unreachable only; globals.d.ts hand-declares the mcCore surface (this week: three
  compile errors were declaration drift, not bugs).
  Why: refactors get no help from the compiler; wire shapes live in API.md prose and
  drift (21 /dm routes were registered, 10 documented, until this week).
  Step: (a) `globals.d.ts`'s McCore → `typeof import('../app/core')` (one line, removes
  a whole class of drift). (b) A `shared/wire.ts` (or a PureScript record + membrane
  erasure) for the DM payloads, imported by worker and client. (c) typescript-eslint
  with `@typescript-eslint/no-explicit-any` as a warning and a ratchet test that the
  count only falls. Effort: (a) minutes; (b) a day for DMs; (c) hours.

P1-5  Nothing alerts; the backup mirror was dead
  Evidence: runBackup (lib.ts ~2055) writes backups/comments-<date>.sql.gz nightly
  (cron 30 23 * * *) — no object existed for 2026-09-07..13 in merecatholicity-backups;
  `wrangler d1 export` refuses the database ("cannot export databases with Virtual
  Tables (fts5)"), the likely shared cause; 89 `*_failed` event logs exist but nobody
  reads them; there is no health page or notifier.
  Why: the first time a backup is needed is the wrong time to learn it never ran.
  Step: (a) fix runBackup (dump table-by-table, skip the FTS5 virtual tables and their
  shadow tables — they are derived and rebuilt by triggers). (b) A daily self-check in
  the existing cron that HEADs yesterday's object and posts to the Discord webhook
  (discord_hooks already exists for posts) on absence — the same for `*_failed` counts.
  (c) A /health that reports last backup, last sweep, ledger head. Effort: ~half a day.

P1-6  Deploy and process safety
  Evidence: push = deploy, one environment, no staged rollout; the ledger applies before
  the deploy (the skew window a lone migration commit exploited this week); rollback is
  undocumented (`wrangler rollback` works but nobody wrote the drill); the fixture
  webtest runs by hand from the dev box (Bot Fight Mode 403s CI); two agents committed
  and pushed from one checkout, one re-creating the other's commit under a new SHA.
  Step: (a) a written rollback drill in CICD.md (`wrangler rollback`, revert-and-push for
  the site). (b) `wrangler versions upload` + `versions deploy --percentage` for worker
  changes that touch the schema or crypto. (c) A nightly webtest run from the dev box
  (systemd timer) posting PASS/FAIL to Discord. (d) One git worktree per agent, and
  branches + PR for anything with a migration; write it into CLAUDE.md. Effort: hours.

P2-1  Handler preambles are copy-pasted
  Evidence: 80 `data = await request.json();`, 31 inline POST_LIMIT and 45 READ_LIMIT
  checks in index.ts, while `keyedGated(request, env, bucket)` exists and is used 20×.
  Step: finish the migration to keyedGated/keyed; a `gated(bucket, fn)` wrapper in the
  ROUTES table removes the boilerplate entirely. Effort: a day, mechanical.

P2-2  Identity registration is scattered
  Evidence: `INSERT OR IGNORE INTO profiles (hash, created_at)` at index.ts ×3 (board
  unread, prefs, merecat ask) and durable.ts ×1 (the hub's last-seen stamp). Any keyed
  read creates a member row, which is why the "members" count reads 53 for 6 humans.
  Step: one `registerMember(env, hash, now)`; decide what a member is (a nick, a
  published key or a post — the word "established" already exists in isEstablished)
  and list only those in /dm/directory. Effort: hours.

P2-3  CLAUDE.md has become the long file it warns against
  Evidence: 414 lines / 37 KB "kept short on purpose"; law bullets of 30+ lines; the
  "next migration" pointer drifted twice this week (0015 → 0016 → 0018).
  Step: one-line rules in CLAUDE.md, the prose in INFRASTRUCTURE; derive "next" in a
  test (`ls migrations | tail -1`) or drop it. Effort: hours.

P2-4  INFRASTRUCTURE.md is 381 KB in 301 lines

P2-5  Bundle weight and code-splitting

  Settings, and a short threat-model page. Effort: a day; product decision first.
