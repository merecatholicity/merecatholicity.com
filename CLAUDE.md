## Hosting and delivery

- **GitHub Pages** serves the **`docs/` folder** of `main` (Settings → Pages → Source: Deploy from a branch, `main` `/docs`), published at the folder's contents = the domain root. So `docs/credo.html` is `merecatholicity.com/credo.html`, `docs/emoji/…` is `/emoji/…`. The site is static: every `*.html`, PDF, image, and built artifact under `docs/` is committed and served as-is. **`docs/CNAME`** points Pages at the apex domain and **`docs/.nojekyll`** disables Jekyll. Both MUST live inside the served folder (`docs/`) — this bit hard once: `git mv`-ing the served files out of the root while Pages still served from root removed CNAME from the served location, unbound the custom domain, and 404'd the whole site ("Site not found · GitHub Pages"). If you ever change WHERE the site is served from, the CNAME must move with it, and the switch of the Pages source itself is done via the API/Settings (`PUT /repos/…/pages` `source[path]=/docs`), needing an admin token.
- **Cloudflare** fronts Pages as a proxy (DNS + CDN + edge features). Do not change the SSL mode to Full (strict); the working configuration is deliberate.
- Because the site is prebuilt static files, "deploying" the site is just committing and pushing built output into `docs/`. There is no site build step on the server.
- **`comments.js` is BUILT from TypeScript now (Phase 2C, 2026-08-01).** Edit **`client/comments.ts`** (the typed source), never `docs/comments.js` — that is generated by `npm run build:client` (esbuild transpile-only: strips types + comments, preserves the standalone IIFE; folded into `make bundle`/`npm run build:js`). It stays the no-bundle fallback client (still import-free, reached from the bundle only via `window.mc*`). tsc (strict) covers it via the root `tsconfig.json` (`client/**/*.ts`), so it is no longer in the eslint list. `make jscheck` (lint + tsc) still gates it.
- **Cache-busting `comments.js`.** The built client is included as `comments.js?v=NN` in every commented page (currently 11 includes, `COMMENTS_V` in `scripts/content.py`); bump `NN` with one `sed` across all of them on any `comments.js` change, or Cloudflare serves the stale script. Cloudflare caches each `?v=N` URL independently and treats it as immutable, so **do not fetch a freshly-bumped `?v=N` URL until GitHub Pages has finished deploying the new file** — a probe mid-deploy freezes the OLD bytes under the new key, and the only clean recovery is to bump again to an unpolluted number. To test origin freshness without polluting a real key, fetch a throwaway query string (`comments.js?probe123`), which always misses cache and hits origin. **Confirming the Pages deploy actually landed is optional and usually unnecessary** — pushing the bump is the end of a normal `comments.js` change. Only poll a throwaway `?probe` for a marker from the new bytes when you genuinely need the new client live before a next step (followup headless testing against the live site, or reproducing a bug on prod). With no such followup, there is nothing to wait for, so don't burn turns watching the deploy. `style.css` is unversioned, so CSS changes propagate on Cloudflare's cache TTL rather than instantly.

## Build system

Builds are pinned to `SOURCE_DATE_EPOCH=1784160000` so rebuilds are byte-identical and git only churns when text actually changes. Built artifacts are committed **into `docs/`** (the served folder); the build tools read sources from `book/`, `content/`, `resources/`, `partials/`, `styles/`, `app/` and write into `docs/`. The book PDFs/HTML/docx build **inside `book/`** (the Makefile `cd book &&`s, so `\input` and `\graphicspath{{../docs/}}` resolve locally) and only the final artifact is copied up into `docs/`.

**The JS toolchain is npm (2026-07-31) — deno is GONE.** The repo is now a disciplined npm project: `package.json` + a committed `package-lock.json`, restored with **`npm ci`** into a git-ignored `node_modules/`. Node/npm are **pacman-installed** (`/usr/bin/node`, `/usr/bin/npm`); **NEVER `sudo npm`, never `npm install -g`** — every JS build/lint tool (Tailwind, esbuild, eslint, wrangler) is a per-project devDependency. `esbuild` is pinned **exact** (`"0.24.2"`) for byte-stable bundles; the rest float within the lockfile. The npm scripts are `build:css` (Tailwind), `build:js` (esbuild), `lint` (eslint), `build` (all three), and `worker:deploy`; **the `make` targets wrap them** so `make css`/`make bundle`/`make jscheck`/`make worker-deploy` work exactly as before. Adding a JS dep is `npm install --save-dev <pkg>` (commit the updated lockfile). Note: npm 12 blocks package install-scripts by default — the native binaries (esbuild/wrangler/tailwind) still arrive via their platform optional-dependencies, so the tools run despite the `install-scripts blocked` warnings. See README's "The JavaScript toolchain (npm)".

**Navigation robustness + PWA hardening (2026-08-02).** Born of a live report (iOS PWA white first-add + seconds-blank hops; fast tapping stranding empty pages until a manual refresh). **softNav is LATEST-WINS now** (`app/shell.ts`): every click starts a navigation that supersedes the one in flight (a `navSeq` guard on every mutation + an AbortController on the fetch) — the old `navigating` boolean preventDefault'ed then silently DROPPED every tap made during a fetch, and a HUNG fetch (no timeout) wedged it forever, freezing all soft navigation. Document fetches ride `fetchDoc`: 9s per-attempt timeout (armed through the body read) + 2 retries on network/timeout/429/5xx; ANY terminal failure falls back to `location.href` — the shell never strands a dead page. **The PWA self-update architecture (2026-08-02, sw VERSION v4 — born of a live report: an installed iOS app ran days-old code with no path to healing, and a freshly re-added one rendered tab skeletons with no content).** Root causes, all structural: an installed app is usually RESUMED, not relaunched — a resume fires no navigation, and a navigation was the ONLY moment iOS ever re-checked `sw.js`; and the SW-cached tab skeletons carry their deploy's `comments.js?v=` baked into the markup, so every post-deploy launch ran yesterday's client against today's kernel (mixed-version = the shell paints, the content never does). ## The PureScript application layer

**The site's application/domain logic IS a PureScript kernel; Lit.js is strictly the render layer, and JS is interop only (DOM, effects, crypto).** The migration reached its intended end state — **`purescript/src/Domain/*.purs` is now 17 modules** covering the meaningful application logic (constants, validation, permissions, parsing, routing, identity classification, FTS sanitization), consumed by both the client bundle and the Cloudflare worker. **Coding rules (this is the whole rulebook — there is no separate rules file):** new application logic goes in PureScript as ADTs + newtypes with **smart constructors**, `Maybe`/`Either` instead of null/throw, and **illegal states made unrepresentable** (e.g. `Fts.SafeMatch` has no public constructor, so an un-sanitized FTS MATCH cannot exist; `Auth.AuthState` forbids a hash without a key); keep logic **pure** and push effects (DOM, fetch, crypto, storage, Turnstile, WebSocket) to thin typed FFI at the edges; migrate in **vertical slices** each proven by the four gates below, deleting the JS it replaces (or, for `comments.js`, keeping the classic body as the no-bundle fallback); never recreate the classic JS architecture for its own sake or weaken the types to dodge the boundary. **All new application logic (validation, permissions, state transitions, business rules, parsing) goes in PureScript, not JS.** What deliberately STAYS in JS is interop by design: DOM/Lit rendering, the Turnstile/nacl/WebCrypto/fetch/WebSocket effects, the raw identity key/hash storage (the secret is sent in every keyed request), the DM E2E crypto + `E1.` framing (opaque by contract), and the composer/DM SEND orchestration (Turnstile-gated). The classic per-function bodies in `docs/comments.js` are kept as the **no-bundle fallback** (app disabled / storage blocked ⇒ no `window.mcCore`), NOT dead code. The modules: `Rank`, `Scripture`, `Profile`, `Faith`, `Pseudonym`, `Dm`, `Access`, `Live`, `Board`, `Emoji`, `Fts`, `Route`, `Auth`, `Mute`, `Blocked`, `Compose`. A 26-commit adversarial review (parity/security/robustness vs the pre-migration code) found the kernel clean — one low-severity lookup drift (fixed) — and confirmed the migration fixed several latent bugs (the bio-cap drift, dead scripture autolinks on invalid/leading-zero refs, FTS injection).

**The seam.** PureScript sources live in **`purescript/src/Domain/*.purs`** (plus a thin FFI where a real JS engine is needed — `Domain/Fts.js` runs the exact tokenization regexes so `\S`/`\s` stay byte-identical). The npm-installed `purs` compiles them to **`purescript/output/**/index.js`** (ESM). A small hand-written barrel **`app/core.js`** re-exports what the UI needs; **`app/shell.js`** imports it and sets **`window.mcCore = Core`** (mirroring the existing `window.mcRich`/`mcStore`/`mcApi` bridges). The Lit views under `app/views/` **import from `app/core.js` directly** (typed, tree-shaken); the un-bundled `docs/comments.js` reaches the same functions through **`window.mcCore`** using the exact `if (window.mcCore) return window.mcCore.fn(...) else …classic…` delegate idiom at ~29 sites (each classic branch is the no-bundle fallback). **esbuild needs no command change** — it follows `core.js`'s relative imports into `purescript/output/` and inlines everything into the one committed `docs/app.js`. `purs` emits plain ES with **no `eval`/`Function`**, so CSP `script-src 'self'` holds.

**`app/core.js` is the TRANSLATION MEMBRANE — the ONE audited place types are erased.** PureScript ADTs don't survive the JS boundary (`Maybe`/`Either` compile to `{tag,…}` objects the classic path reads as truthy). So **nothing exported on `window.mcCore` (or imported by `comments.js`) returns a raw PS constructor**: the barrel erases `Maybe a → a|null`, `Either e a → {ok:true,value}|{ok:false,error}`, `data T → discriminant string`. Keep it tiny; type safety lives inside PureScript. A `webtest` asserts the `window.mcCore` shape so a PS rename fails headlessly.

**Toolchain (npm-12 + byte-determinism + no-globals safe).**
- **The `purs` compiler is an npm devDependency** (`purescript@0.15.16`, exact-pinned) restored by `npm ci` like everything else. npm-12 blocks its install-script by default, so the approval is **committed in `package.json`'s `allowScripts`** (`"purescript@0.15.16": true`) — `npm ci` then runs the approved postinstall and materializes **`node_modules/.bin/purs`**. **No vendored binary** (`make purs`/`vendor/purs/` are gone).
- **`spago`** is a clean pure-JS **devDependency** (no install-script); it only resolves deps + orchestrates, shelling out to the npm-installed `purs` (found on PATH). Package set pinned in `purescript/spago.yaml` (`registry: 80.2.0`).
- **`make psbuild`** = `npm run build:ps` = `rm -rf purescript/output` (determinism guard) then `spago build` (spago finds `node_modules/.bin/purs` on the npm-run PATH) → `purescript/output/`. **`make bundle` runs it via `npm run build:js`** (which does `build:ps` then esbuild), and a bare `npm run build:js` is self-sufficient too. **`make pstest`** runs the Node-native pure-unit tests (`tests/purescript/*.test.mjs`, one file per `Domain` module, over the compiled ESM output — the PureScript slice of `make tests`; see the **Testing policy** section).
- **eslint**: `eslint.config.js` **ignores `purescript/output/**`** (generated) and **lints `app/core.js` + `purescript/src/**/*.js`** (hand-written FFI). `.gitignore`: `purescript/output/`, `purescript/.spago/`. The committed artifact stays `docs/app.js` (PS output is inlined into it); `output/` is never committed.
- **`?v=N` law applies to PS exactly as to any bundle change**: `docs/sw.js` caches `app.js` by exact URL, so any `docs/app.js` byte change **must** bump `app.js?v=N` in `docs/nav.js`. Determinism holds given pinned `purs` + pinned package set + the `rm -rf output` guard; a `purs` version bump is a deliberate, reviewed, `?v=`-bumping event.

**A slice ships only when all FOUR gates pass:** (1) byte-deterministic rebuild (`make bundle` twice → `git diff --exit-code docs/app.js`); (2) parity with the JS it replaces (`make pstest` + headless delegate-vs-classic equality — this licenses deleting the classic fallback); (3) `npm run lint` green; (4) headless render parity against a **locally served** bundle (`make serve` + `MC_BASE=http://127.0.0.1:8000` — never test an unshipped slice against prod), console clean. Then bump `?v=` and ship. (Where a classic fallback is genuinely dead — a bundled-only view — delete it as the closing step; the `comments.js` fallbacks are kept ON PURPOSE as the no-bundle path.)

**Lit stays presentational.** "Keep Lit unchanged" = the library (vendored `app/vendor/lit-all.min.js`), the ``html`` templates, and the rendered output stay; the view **files** get thinner as reducers/permission-checks/math/parsing move into PS. **FFI is a small, typed escape hatch** in `purescript/src/Ffi/*` for the genuine browser surfaces only: WebSocket lifecycle (`app/live.js`), `fetch`/retry/pace (`app/api.js`), WebCrypto AES-GCM + tweetnacl X25519 for DM E2E, `localStorage`, DOM-safe render (no `innerHTML`), Turnstile, history/popstate soft-nav, the Audio dock. Never move ordinary logic into JS to dodge PureScript.

**The worker shares the kernel — DONE.** `comments-worker/src/index.js` **imports the same `purescript/output/`** for its 9 shared surfaces — `Rank` (ranks), `Faith` (`FAITHS`/`FAITH_LABELS`), `Profile` (`MAX_*` caps), `Pseudonym` (`displayName`), `Dm` (`DM_TTLS`), `Scripture` (the `/config` bible table + `MERECAT_BIBLE`'s 66-book core), `Fts` (the `SafeMatch` `buildMatch`/`merecatMatch`), `Board` (`CAT_META`/`BOARD_CATS`/`ADMIN_CAT`), `Emoji` (`EMOJI_PACKS`/`NAMED_EMOJI`). Every constant/table/validator the worker and client both held is now single-sourced from one kernel — the **"two files must stay identical" hazard class is closed at the root**, and the old bio-cap drift (client 1000 vs worker `MAX_BIO` 500) is fixed (`Profile.limits.bio = 500`, one source). `make worker-deploy` runs `psbuild` before wrangler; wrangler's esbuild follows the `../../purescript/output/...` imports and inlines them (CSP-clean, no `eval`). When adding a NEW shared constant, put it in a `Domain.*` module and import it both sides — do not reintroduce a duplicated copy.

## Testing policy

**Tests here exist to CLARIFY what the code does for a human reading the repo, and to GUARD the rules that would break silently — not to chase coverage.** There is **no numeric coverage target** (no "99%"), and no test for a trivial getter. Write the tests a human would write: each names a real behavior and locks it; the assertions document ACTUAL behavior (derive expected values by reading/running the code, never guess). If a piece of logic is worth a human understanding it and getting it wrong would break something, it deserves a test; otherwise it doesn't. Tests that clarify the codebase are the goal — AI-compulsion "test everything" is the anti-goal.

**`make tests`** is the standing unit suite (`tests/`, full how-to in `tests/README.md`). It runs `psbuild` first (so the compiled `Domain.*` output the tests import is fresh), then: **PureScript + JS via Node's built-in runner** (`node --test` + `node:assert/strict` — no new dep, matches the stdlib/lockfile discipline) over `tests/**/*.test.mjs`, and **Python + the CSS/build invariants via stdlib `unittest`** (pytest is not installed) over `tests/**/test_*.py`. `make pstest` is the fast PureScript-only alias. One file per concern: `tests/purescript/` (one per `Domain` module — the rulebook: rank, FTS injection-safety, route priority, scripture, access, auth, pager, …), `tests/js/` (the `app/core.js` membrane coercions, `store.js` cache/dedup, `api.js` request+invalidation), `tests/worker/` (the security-critical worker helpers), `tests/py/` (nav/frontmatter/converter helpers, the cross-language slug parity, the serve/llm math), `tests/css/` (the Tailwind `source(none)`/freshness invariants on the committed `docs/style.css`).

**Three layers, so a new test has an obvious home.** Layer 1 = these unit tests (`tests/`): pure, hermetic, fast. Layer 2 = `webtest/`: headless Chromium render/soft-nav parity, mostly vs prod (see below). Backend regression = `local/tests/`: the librarian RAG backend, spins up real model servers. A pure function (validation, permission, parsing, math, a state transition, a formatting rule) is Layer 1. Something only observable when client JS runs in a real browser (anchor jumps, board/DM rendering, scroll-to-comment) is Layer 2 — don't force it into the unit layer. The center of gravity is the PureScript `Domain` layer: its modules already distil the app's rules, so each `tests/purescript/*.test.mjs` reads as that rule's spec (and covers the classic no-bundle fallbacks too, which mirror the same logic). A few pure worker helpers that aren't in PureScript yet — IP/ban-key normalization and the back-room privacy predicate `boardEventPublic` — were extracted into `comments-worker/src/pure.js` so they can be unit-tested in plain Node (`index.js` itself imports `cloudflare:workers` and can't be); behavior is unchanged, and the extraction is a stepping stone toward the PureScript kernel.

**`make tests` must pass before any commit or push (standing gate).** Green unit tests are a precondition to shipping — run `make tests` before you commit/push, and before `make worker-deploy` (which also runs `jscheck` + `psbuild`). If a change breaks a test, either the change is wrong or the rule genuinely moved: fix the code, or update the test IN THE SAME COMMIT to document the new rule (never delete a test to make a red build green). This sits alongside the existing gates — `make jscheck` after any worker/client JS edit, `make check` for links — and the four PureScript ship gates.

**WHEN to add a test (the standing rule for future work).** When you add or change a rule — a validation, a permission, a state transition, a parser, a piece of math, a shared constant/table — add or adjust its test **in the same change**; the test is that rule's documentation (the same discipline as the `?v=` bump and the nav `PAGES` list). Prefer to put new application logic in a `Domain.*` module and test it under `tests/purescript/` — that keeps the rule single-sourced (client + worker) AND testable in one move. Do **not** add tests for trivial one-liners or for DOM/network-coupled code (that is Layer 2's job; the pure logic under it usually already lives in a `Domain` module). A slice's Layer-1 parity test is one of the four ship gates above and is what licenses deleting a classic fallback.

## Verifying the live site (headless browser)

`make check` (linkcheck) is the static-file gate, and **`make tests`** is the hermetic unit gate (see the Testing policy above). Anything that depends on **client JS actually running** — anchor jumps, pagination-aware scroll-to-comment, board/DM rendering — cannot be verified with either, only with a real browser. A headless Chromium is preinstalled at `~/.cloakbrowser`: several `chromium-<version>/` dirs, each holding a matching `chrome` and `chromedriver`. There is no node/npm, so drive it through chromedriver's WebDriver HTTP API using Python stdlib only:

- Launch `~/.cloakbrowser/chromium-<ver>/chromedriver --port=N` in the background; poll `GET /status` until ready.
- `POST /session` with `capabilities.alwaysMatch.goog:chromeOptions.binary` set to the sibling `chrome`, args `--headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage --window-size=1200,800 --user-data-dir=<scratchpad>`. Pair `chrome` and `chromedriver` from the **same** version dir or the session refuses to start.
- `POST /session/<id>/url` to navigate (full URL including the `#comment-N` hash), then poll `POST /session/<id>/execute/sync` running a JS probe until the async board fetch has rendered, and read back DOM facts (element presence, `.board-pages strong` = active page, `window.scrollY`, `getBoundingClientRect().top`).
- Always `DELETE /session/<id>` and SIGTERM chromedriver when done.

This catches what curl cannot: e.g. that `community.html?topic=<t>#comment-<id>` resolves to the correct page and scrolls to the comment. (The client sends `&find=<id>` only when there is no explicit `&p`; the worker then counts prior live replies to compute the page. A bare `Math.max(1, …)` default for the page number silently disables this — the page defaults to 1 and the jump strands on page one.)

Cloud path (`merecatPump`): a vanished reader never errors writes — the runtime just stops pulling, an awaited `writer.write` **parks forever on backpressure**, and the hang-detector kills the whole invocation before any storage line runs ("code had hung and would never generate a response" in the tail).
