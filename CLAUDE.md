# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This file is about how the **website and its infrastructure** work: the GitHub Pages side, the Cloudflare Workers/D1/R2 side, and the build system that ties them together.

If you are working on any text-based content and `CONTEXT_DUMP.txt` is present in the repo root, ingest it first. This file stays focused on infra.

**Never store sensitive information in this file** (or anywhere committed): no API tokens, secrets, private keys, or unpublished credentials. Cloudflare Worker secrets are set with `wrangler secret put`, not in source. The identity hashes and Turnstile sitekeys that do appear in the repo are public by design.

**Keep this file current.** When infrastructure changes in an important way — a hosting or DNS pivot, a new or retired Worker, a change to how builds or deploys run, a plan or quota policy change — update this file in the same change.

## Hosting and delivery

- **GitHub Pages** serves the repo root directly. The site is static: every `*.html`, PDF, image, and built artifact is committed and served as-is. `CNAME` points Pages at the apex domain.
- **Cloudflare** fronts Pages as a proxy (DNS + CDN + edge features). Do not change the SSL mode to Full (strict); the working configuration is deliberate.
- Because the site is prebuilt static files, "deploying" the site is just committing and pushing built output. There is no site build step on the server.
- **Cache-busting `comments.js`.** The client is included as `comments.js?v=NN` in every commented page (currently 9 includes); bump `NN` with one `sed` across all of them on any `comments.js` change, or Cloudflare serves the stale script. Cloudflare caches each `?v=N` URL independently and treats it as immutable, so **do not fetch a freshly-bumped `?v=N` URL until GitHub Pages has finished deploying the new file** — a probe mid-deploy freezes the OLD bytes under the new key, and the only clean recovery is to bump again to an unpolluted number. To test origin freshness without polluting a real key, fetch a throwaway query string (`comments.js?probe123`), which always misses cache and hits origin. **Confirming the Pages deploy actually landed is optional and usually unnecessary** — pushing the bump is the end of a normal `comments.js` change. Only poll a throwaway `?probe` for a marker from the new bytes when you genuinely need the new client live before a next step (followup headless testing against the live site, or reproducing a bug on prod). With no such followup, there is nothing to wait for, so don't burn turns watching the deploy. `style.css` is unversioned, so CSS changes propagate on Cloudflare's cache TTL rather than instantly.

## Build system

Builds are pinned to `SOURCE_DATE_EPOCH=1784160000` so rebuilds are byte-identical and git only churns when text actually changes. Built artifacts are committed.

- `./build-confession.sh` — book PDF (`Mere_Catholicity.pdf`) via pdflatex (run twice for refs/TOC).
- `make html` — HTML editions (`book.html`, `bishop-presbyter.html`) via pandoc, plus resources pages, then runs the link check.
- `make publish` — KDP paperback PDF (same `confession.tex`, `\PAPERBACK` flag, separate jobname).
- `make logos` — Logos/Verbum `.docx`.
- `make menu` — regenerate all site navigation from `nav.yml`, then rebuild html.
- `make check` — `python linkcheck.py`; verifies every internal href/src and `#fragment` on the site resolves. This is the only automated test.
- `make chart-pdfs` — print chart pages to PDF with headless `/usr/bin/chromium` (note: `~/bin/chromium` is an emacs wrapper, not a browser).
- `make serve` — local server on port 8000.
- `make comments-backup` — export the live D1 comments DB to `comments-backup.sql` (kept out of git).
- `make librarian` — rebuild and push everything merecat (the librarian bot) knows: corpus chunks, persona, config, all from `librarian/` (see the merecat section below and `librarian/README.md`).

**Navigation** is generated: `nav.yml` is the single source. `nav.py` renders `nav.html` and rewrites the inline nav block in every page listed in the `PAGES` array at the top of `nav.py`. A new site page must be added to that list or `make menu` will not touch it.

**Resources** (`resources/`) are public-domain texts rebuilt as our own LaTeX. `*2tex.py` scripts convert preserved sources into `*-body.tex`; the `WORKS` list in `resources/Makefile` maps each source to its published root PDF, and outputs land in the repo root so Pages serves them.

**The complete Schaff corpus** (the whole Ante-Nicene Fathers, 9 vols., the Nicene and Post-Nicene Fathers, First and Second Series, 14 vols. each — 36 volumes, NPNF-2 Vol. 14 being the already-published `councils.html` — plus Schaff's own **History of the Christian Church**, 8 vols. `hcc1`–`hcc8`, and **The Creeds of Christendom**, 3 vols. `creeds1`–`creeds3`: 47 volumes in all) is rendered by `resources/schaff.py`, a whole-volume driver over the shared `ccel2tex.convert_work`. The History and Creeds volumes put their chapters at `div2` under one container `div1`, so they convert with `make_volume_heading(deep=True)` (top divisions always skip-promote) and `table_cells=True` (their parallel Greek/Latin|English texts sit in `<table>` rows whose cells often carry bare text — the Converter's opt-in td-as-paragraph mode keeps it; off elsewhere so the older bodies stay byte-stable). `creeds3` mis-nests a `<note>` inside a `<note>` (Westminster proof-texts) — the Converter flattens nested notes. `make body` regenerates all of it; `make pdf` builds every root PDF (`History_of_the_Christian_Church_Vol_*.pdf`, `Creeds_of_Christendom_Vol_*.pdf`, and the Fathers sets) via the same `PDF_RULE` machinery; `make -C resources schaff-html` (run by `make html`) renders each `<id>.html`. The library is listed on `credo.html#library` (under the consensus-of-the-Fathers section) and on `library.html` (`#schaff`, `#history`, `#creeds`). **Volume source XML and per-volume intermediate PDFs are git-ignored** (reproducible): `make -C resources schaff-fetch` re-downloads every CCEL ThML XML; the committed `<id>-body.tex`/`<id>.tex` and the published root PDFs are what the site serves. **Project Gutenberg books** convert via `resources/gutenberg2tex.py` (the third flat-HTML converter beside `dr2tex.py`/`kjv2tex.py`, reusing the dev2tex engine): **The Faith of Our Fathers** (`gibbons`, PG 27435), **An Apology of the Church of England** (`jewel`, PG 17678), and **the Ninety-Five Theses bound with Concerning Christian Liberty** (`luther-primary`, PG 274 + 1911 — a WORKS entry may list several `srcs` bound as one volume, each with its own `firsts` cut). **The Douay-Rheims Bible** (`douay-rheims.html` / `Douay-Rheims_Bible.pdf`, ~1,744 pp.) is the whole Challoner-revision Catholic Bible, converted by `resources/dr2tex.py` from the preserved Project Gutenberg HTML (`resources/douay-rheims-src.html`, ebook 1581). That source is flat, not ThML, so it has its own tiny parser: `<h2>` testaments → `\xchapter`, `<h3>` books → `\xsection` (new page each), `<h4>` chapters → `\xsubsection`, `<p>` verses (leading `N:M.` bolded), `p.sp2` arguments → `\drarg`, `p.expl` Challoner notes → `\drnote` (macros defined in the wrapper `douay-rheims.tex`). It is a normal `WORKS` entry for the PDF and has its own stanza in the `html` target (it needs the `\drarg`/`\drnote` seds and bracket-protection); listed on `credo.html#scriptures`.

**The Catena Aurea** (Aquinas' Golden Chain on the four Gospels, `catena-{matthew,mark,luke,john}.html` / `Catena_Aurea_*.pdf`) is converted by `resources/catena2tex.py` from the fisheaters PDFs (`resources/catena-src/xaquinas-*.pdf`, git-ignored — re-downloadable) via `pdftotext`. The extracted text is clean (only page-number lines and form-feeds to drop); the parser keys on `CHAP. N`, verse-range lines (`1:1`, `2:1–2`), and Father **attributions** matched against a fixed roster (`KNOWN`) so noise like "THE."/"AMEN." never splits a paragraph. It emits **single-argument** macros only — `\cachapter`, `\caref`, `\calemma`, `\cafather{Name}` — so the HTML `catena-html` target can rewrite each with one `sed` (a 2-arg macro would leave a stray brace); `\cafather{X}` carries the trailing period into the bold attribution. `finalize()` NFC-composes, drops orphan combining marks and bidi controls, and wraps Greek/Hebrew citation runs in `\textgreek`/`\texthebrew` (the wrapper carries the same `textalpha` guard as the Schaff volumes). Four `WORKS` entries build the PDFs; listed on `credo.html#catena` under the consensus-of-the-Fathers section.

**The King James Bible** (`kjv.html` / `King_James_Bible.pdf`, ~1,415 pp.) is the 66-book Authorized Version, converted by `resources/kjv2tex.py` from Project Gutenberg ebook 10 (`resources/kjv-src.html`, committed). Same flat shape as the Douay-Rheims but chapters are *not* marked — the chapter number lives in each verse's `C:V` ref, and a single `<p>` often packs several verses, so the parser splits on every `C:V` and emits a `\xsubsection{Chapter N}` when the number advances (31,102 verses, 1,189 chapters — both exact). Gutenberg's KJV carries no Apocrypha, which matches the Scourby audio (Phase 2) exactly. A `WORKS` entry + a DR-style `html` stanza; listed on `credo.html#scriptures` and the Library. The DRBO spoken Bible (sanctusmission.com) is linked there as a secondary external resource.

**The Summa Theologica** (`summa-fp.html`…`summa-xp.html` / `Summa_Theologica_*.pdf`, five parts, ~3,800 pp. total) is converted by `resources/summatheologica2tex.py` from the git-ignored CCEL HTML tree (`resources/summa-src/`, re-fetch with `make -C resources summa-fetch`). The old `<br>`-laid-out HTML has **unclosed `<P>` tags**, so the parser (an HTMLParser) flushes at each boundary, not on `</p>`, and keys on the files' precise structural **HTML comments** (`SMT <PART> Q[n] A[a] Obj./OTC/Body/R.O./Thes./Out.`) plus `<H3 Align="Center">` (treatise + question title) and `<H3 Align="Left">` (article "Whether…?"). Emits the shared `\xchapter`(treatise)/`\xsection`(question)/`\xsubsection`(article) macros with scholastic labels bolded, reusing `catena2tex.finalize`. Split into its five parts (FP/FS/SS/TP/Supplement), five `WORKS` entries + a `summa-html` stanza; listed **only** on the Library page.

**The Newman corpus** (55 works — the whole public NewmanReader corpus, `arians.html`…`verses.html` + one root PDF each) is rendered by `resources/newman.py`, a whole-corpus driver modeled on `schaff.py` that reuses the dev2tex engine (the same passes behind `development.html`/`consulting.html`). One `WORKS` table (id, `path` for a multi-file work or `page` for a single page, section, title, pdf, provenance, blurb, `exclude`, `notes_appendix`) drives fetch → convert → wrapper → `resources/newman.mk` (`NEWMAN_PDFS`/`NEWMAN_HTML`, `-include`d by the Makefile; `make -C resources newman-html` runs in `make html`). `make -C resources newman-fetch` re-spiders newmanreader.org into git-ignored `resources/newman-src/<id>/` (file set = the work's `index.html` same-dir links, fragments dropped, nested sub-work indexes resolved recursively). Newman's endnotes become `\footnote`s at their reference points, keyed on the `#noteN` **anchor** (not the visible text — some works write a bare "[Note]"); the id scheme spans `note12`/`mnote12` (margin)/`noteA` (lettered), which Athanasius' historical tracts use all at once. A chapter split across files (`chapter6-1/-2`) is detected by the absence of its own `<h2>`. LaTeX-safety passes: `_heal_emphasis` (no `\par`/`\begin{quote}` inside a text command), `_cap_quotes` (≤5 nesting, orphan `\end{quote}` dropped), `_map_symbols`, `\\[`→`\\{}[`, then PUA-sentinel and known-HTML-tag sweeps. Four source files drop a few footnote markers (cross-file note targets; text intact). Listed on `library.html#newman` as a period shelf (Anglican / Catholic / Miscellaneous) beside the earlier `development`/`consulting`.

**KJV Scourby audio** is Alexander Scourby's public-domain reading, one MP3 per chapter, **self-hosted on Cloudflare R2** (the site can't put 3.26 GB in git/Pages). A third R2 bucket **`merecatholicity-audio`** holds the objects under `kjv/<bookslug>/<chapter>.mp3` (66 canonical books, no Apocrypha — matching Gutenberg's KJV), served from the **custom domain `audio.merecatholicity.com`** (a `wrangler r2 bucket domain add` on the zone; the `pub-*.r2.dev` URL also works but the custom domain is stable and Cloudflare-cached, with range requests for seeking). The client is `kjv-audio.js` (loaded via `kjv-tail.html`, the KJV page's pandoc `-A` include instead of the plain footer): it walks the page's `h2` book headings (canonical order → its `SLUGS` array) and `h4` "Chapter N" headings, grafts a ▶ button onto each chapter, and drives one shared `<audio>` element that auto-advances to the next chapter. **Re-uploading:** `scratchpad/upload_kjv_audio.py` downloads the 66 per-book ZIPs from earnestlycontendingforthefaith.com, extracts the per-chapter MP3s, and `wrangler r2 object put`s each — **with `--remote`**, the essential gotcha: without it wrangler writes to a *local* simulated store and the real bucket stays empty (the public URL 404s). **The Library page** (`library.html`) is a hand-authored master catalog of every hosted work (Scripture, Summa, the Fathers, the Schaff library, councils, Newman, the rule of prayer, our own papers), generated once via `scratchpad/gen_library.py` (which imports `schaff.VOLUMES` so the 37 volumes never drift) then spliced into the `resources.html` skeleton. It replaced **Sources** in the nav (`nav.yml`: `Library: library.html`; added to `nav.py`'s `PAGES`); `resources.html` stays in place, off-nav. A nav change rebuilds every pandoc page's baked-in nav, so it is followed by a full `make html`.

**Deep-linking (`deeplink.js`).** Every generated Scripture/Fathers page is addressable down to the verse or paragraph, entirely **client-side** so no page had to be rebuilt: `nav.js` (already on every page) injects `deeplink.js`, which no-ops unless the page has pandoc `.unnumbered` headings. It stamps each **KJV verse** with a canonical `id="<bookslug>-<chapter>-<verse>"` (walking the 66 book `<h2>` in canonical order for the slug — verses get the id but no visible marker, ~31k would be noise), and every **Fathers heading/paragraph** with an id (headings keep pandoc's own slug so the TOC still resolves; paragraphs hang off the nearest heading as `<heading-id>__p<n>`). Each heading and Fathers paragraph gets a hover-revealed `¶` marker (one delegated click handler, not thousands) whose click copies the permalink; arriving at a `#hash` scrolls to it and `:target`-tints it (style.css). **Scripture autolinking + picker (`comments.js`).** `BIBLE` (a book→slug table with every abbreviation, common-word 2-letter forms omitted) yields a regex fragment spliced into `INLINE_MD`; `appendRich` turns `Rom 8:28-30`/`John 3:16` into a same-site link to `kjv.html#romans-8-28` — a bare book name never links (a chapter:verse is required). A `✝ Scripture` toolbar button (beside the emoji picker, in `mdEditor`) opens `buildScripturePanel`, which lazily fetches **`kjv.json`** (book→chapter→verse text, generated by `resources/kjv-json.py`, the same lazy pattern as `emoji-data.json`) and inserts the chosen passage as a `>` blockquote plus the reference. On desktop, hovering an autolinked reference pops the verse text (`scriptureHover`, reusing the cached `kjv.json`). Any `comments.js` change needs the usual `comments.js?v=NN` bump; `deeplink.js`/`nav.js`/`style.css` are unversioned (cache-TTL).

## Verifying the live site (headless browser)

`make check` (linkcheck) is the only static test. Anything that depends on **client JS actually running** — anchor jumps, pagination-aware scroll-to-comment, board/DM rendering — cannot be verified with curl, only with a real browser. A headless Chromium is preinstalled at `~/.cloakbrowser`: several `chromium-<version>/` dirs, each holding a matching `chrome` and `chromedriver`. There is no node/npm, so drive it through chromedriver's WebDriver HTTP API using Python stdlib only:

- Launch `~/.cloakbrowser/chromium-<ver>/chromedriver --port=N` in the background; poll `GET /status` until ready.
- `POST /session` with `capabilities.alwaysMatch.goog:chromeOptions.binary` set to the sibling `chrome`, args `--headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage --window-size=1200,800 --user-data-dir=<scratchpad>`. Pair `chrome` and `chromedriver` from the **same** version dir or the session refuses to start.
- `POST /session/<id>/url` to navigate (full URL including the `#comment-N` hash), then poll `POST /session/<id>/execute/sync` running a JS probe until the async board fetch has rendered, and read back DOM facts (element presence, `.board-pages strong` = active page, `window.scrollY`, `getBoundingClientRect().top`).
- Always `DELETE /session/<id>` and SIGTERM chromedriver when done.

This catches what curl cannot: e.g. that `community.html?topic=<t>#comment-<id>` resolves to the correct page and scrolls to the comment. (The client sends `&find=<id>` only when there is no explicit `&p`; the worker then counts prior live replies to compute the page. A bare `Math.max(1, …)` default for the page number silently disables this — the page defaults to 1 and the jump strands on page one.)

## Cloudflare Workers (dynamic backend)

The static site delegates its two dynamic features to Workers. Both are **free-tier only** — any new worker feature must stay within Cloudflare's free plan. Deploy each from its own directory with `deno run -A npm:wrangler deploy` (wrangler runs through deno; there is no npm/node setup). Config is in each directory's `wrangler.jsonc`.

- **`comments-worker/`** — the comments backend. Routed on the zone at `/api/comments*`, so it is same-origin with the pages (no CORS). Uses **D1** for storage, **Turnstile** as the spam gate, **Workers AI** (Llama Guard) for screening (`MODERATION_MODE` var), rate-limit bindings for per-IP throttles, and a monthly cron that dumps D1 to **R2** (`merecatholicity-backups`, 90-day retention). Client side is `comments.js`; a page opts in with `<section class="comments" data-comments>` plus the script (the book edition gets it via `book-tail.html`). Identity is a browser-generated key; the server stores only its SHA-256 and derives a pseudonym from the hash. NOTE: the pseudonym/reserved wordlists — and the faith-declaration codes (the `FAITHS` list in the worker, the `FAITH` label map and `FAITH_ORDER` in the client) — are duplicated in `comments.js` and `comments-worker/src/index.js` and must stay identical. Every member picks a faith (`nicene` / `indo-european` / `seeker`) at signup; it lives on the `profiles` row, is filled from the first post (fill-only, never overwriting an edited value), is changed in the profile editor, and shows under the author's name on posts and on the profile.
- **Moderation is all in-platform** (the comments worker sends no email at all now; the old signed-link moderation emails are gone, and its only remaining secret is `TURNSTILE_SECRET`). Admin powers live in the per-comment user-fingerprint dropdown: **lock/unlock** an identity (reversible; a locked hash is logged out and refused every keyed call), **delete user and all posts** (soft-deletes their comments, removes profile+avatar, and locks the hash), and **ban IPs** (every address known for the identity, each bannable alone or all at once behind a confirm that flags a shared/CGNAT v4). A `blockedReason()` gate on every keyed endpoint (writes + the DM unread poll) returns `{blocked}`, and the client logs the user out and redirects to `terms.html` where `flash.js` shows a non-fading banner. Public/cached reads are never gated. OR parent_id=?`), then DMs the original poster an automated notice, from the moving admin and delivered unheld, with a link to its new home. - **Unread threads, mute, and profile post-history** ride the same worker (a retention/UX trio). **New since last visit:** a `thread_reads` table (`PRIMARY KEY (hash, topic_id)`; `topic_id = 0` is a per-user *read-all floor* set lazily on the first `/board/unread` call, so a newcomer starts all-read instead of facing a wall of "new") drives four keyed, `blockedReason`-gated POSTs — `/board/unread` (total + per-category new counts; a topic is new when its `last_at` beats the reader's per-thread `read_at`, or the floor), `/board/reads` (the unread topic ids for one category, so `viewCat` marks them `● new`), `/board/read` (upsert `read_at=now` on opening a topic), and `/board/read-all` (reset the floor to now and drop the now-redundant per-thread rows — the **Mark all read** action on the board index). A poster has seen their own post, so `handlePost` also advances the author's `thread_reads.read_at` to their new comment's `created_at` (the thread's fresh `last_at`) for a **live** board post — without this a member's own reply reads back as one unread when they return to the index, since posting raises `last_at` past the `read_at` that opening the thread set. **Mute** is purely client-side (an `mc-muted` localStorage hash list; `isMuted`/`toggleMute`): a muted member's in-thread posts collapse to a *show* placeholder, toggled from the post head or the profile — no server call, orthogonal to the DM shadow-block. **Post-history:** `GET /board/author?hash=&p=` (READ_LIMIT, `cacheHeader`) returns a member's own live forum posts, newest-first and paginated, rendered as a **Recent posts** list on their profile — deferred behind a *Show recent posts* link so a profile view makes no post-history call until the reader asks (a worker-load saving).
