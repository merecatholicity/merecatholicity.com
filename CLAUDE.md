## Hosting and delivery

- **GitHub Pages** serves the **`docs/` folder** of `main` (Settings → Pages → Source: Deploy from a branch, `main` `/docs`), published at the folder's contents = the domain root. So `docs/credo.html` is `merecatholicity.com/credo.html`, `docs/emoji/…` is `/emoji/…`. The site is static: every `*.html`, PDF, image, and built artifact under `docs/` is committed and served as-is. **`docs/CNAME`** points Pages at the apex domain and **`docs/.nojekyll`** disables Jekyll. Both MUST live inside the served folder (`docs/`) — this bit hard once: `git mv`-ing the served files out of the root while Pages still served from root removed CNAME from the served location, unbound the custom domain, and 404'd the whole site ("Site not found · GitHub Pages"). If you ever change WHERE the site is served from, the CNAME must move with it, and the switch of the Pages source itself is done via the API/Settings (`PUT /repos/…/pages` `source[path]=/docs`), needing an admin token.
- **Cloudflare** fronts Pages as a proxy (DNS + CDN + edge features). Do not change the SSL mode to Full (strict); the working configuration is deliberate.
- Because the site is prebuilt static files, "deploying" the site is just committing and pushing built output into `docs/`. There is no site build step on the server.
- **Cache-busting `comments.js`.** The client is included as `comments.js?v=NN` in every commented page (currently 9 includes); bump `NN` with one `sed` across all of them on any `comments.js` change, or Cloudflare serves the stale script. Cloudflare caches each `?v=N` URL independently and treats it as immutable, so **do not fetch a freshly-bumped `?v=N` URL until GitHub Pages has finished deploying the new file** — a probe mid-deploy freezes the OLD bytes under the new key, and the only clean recovery is to bump again to an unpolluted number. To test origin freshness without polluting a real key, fetch a throwaway query string (`comments.js?probe123`), which always misses cache and hits origin. **Confirming the Pages deploy actually landed is optional and usually unnecessary** — pushing the bump is the end of a normal `comments.js` change. Only poll a throwaway `?probe` for a marker from the new bytes when you genuinely need the new client live before a next step (followup headless testing against the live site, or reproducing a bug on prod). With no such followup, there is nothing to wait for, so don't burn turns watching the deploy. `style.css` is unversioned, so CSS changes propagate on Cloudflare's cache TTL rather than instantly.

## Build system

Builds are pinned to `SOURCE_DATE_EPOCH=1784160000` so rebuilds are byte-identical and git only churns when text actually changes. Built artifacts are committed **into `docs/`** (the served folder); the build tools read sources from `book/`, `content/`, `resources/`, `partials/`, `styles/`, `app/` and write into `docs/`. The book PDFs/HTML/docx build **inside `book/`** (the Makefile `cd book &&`s, so `\input` and `\graphicspath{{../docs/}}` resolve locally) and only the final artifact is copied up into `docs/`.

**The JS toolchain is npm (2026-07-31) — deno is GONE.** The repo is now a disciplined npm project: `package.json` + a committed `package-lock.json`, restored with **`npm ci`** into a git-ignored `node_modules/`. Node/npm are **pacman-installed** (`/usr/bin/node`, `/usr/bin/npm`); **NEVER `sudo npm`, never `npm install -g`** — every JS build/lint tool (Tailwind, esbuild, eslint, wrangler) is a per-project devDependency. `esbuild` is pinned **exact** (`"0.24.2"`) for byte-stable bundles; the rest float within the lockfile. The npm scripts are `build:css` (Tailwind), `build:js` (esbuild), `lint` (eslint), `build` (all three), and `worker:deploy`; **the `make` targets wrap them** so `make css`/`make bundle`/`make jscheck`/`make worker-deploy` work exactly as before. Adding a JS dep is `npm install --save-dev <pkg>` (commit the updated lockfile). Note: npm 12 blocks package install-scripts by default — the native binaries (esbuild/wrangler/tailwind) still arrive via their platform optional-dependencies, so the tools run despite the `install-scripts blocked` warnings. See README's "The JavaScript toolchain (npm)".

## The PureScript application layer (migration in progress)

**The site's application/domain logic is migrating to PureScript, with Lit.js kept strictly as the render layer.** Full rulebook + phase ledger: **`PURESCRIPT.md`** (repo root). This section is the operative mechanics; when in doubt, `PURESCRIPT.md` governs intent. The center of gravity moves toward PureScript over many vertical slices; **all new application logic (validation, permissions, state transitions, business rules, parsing) goes in PureScript, not JS** — JS is increasingly interop only.

**The seam (already proven end-to-end, Phase 0).** PureScript sources live in **`purescript/src/Domain/*.purs`** (and `Ffi/*` later). The vendored `purs` compiles them to **`purescript/output/**/index.js`** (ESM). A small hand-written barrel **`app/core.js`** re-exports what the UI needs; **`app/shell.js`** imports it and sets **`window.mcCore = Core`** (mirroring the existing `window.mcRich`/`mcStore`/`mcApi` bridges). The Lit views under `app/views/` **import from `app/core.js` directly** (typed, tree-shaken); the un-bundled `docs/comments.js` reaches the same functions through **`window.mcCore`** using the exact `if (window.mcCore) return window.mcCore.fn(...) else …classic…` delegate idiom it already uses 13+ times. **esbuild needs no command change** — it follows `core.js`'s relative imports into `purescript/output/` and inlines everything into the one committed `docs/app.js`. `purs` emits plain ES with **no `eval`/`Function`**, so CSP `script-src 'self'` holds.

**`app/core.js` is the TRANSLATION MEMBRANE — the ONE audited place types are erased.** PureScript ADTs don't survive the JS boundary (`Maybe`/`Either` compile to `{tag,…}` objects the classic path reads as truthy). So **nothing exported on `window.mcCore` (or imported by `comments.js`) returns a raw PS constructor**: the barrel erases `Maybe a → a|null`, `Either e a → {ok:true,value}|{ok:false,error}`, `data T → discriminant string`. Keep it tiny; type safety lives inside PureScript. A `webtest` asserts the `window.mcCore` shape so a PS rename fails headlessly.

**Toolchain (npm-12 + byte-determinism + no-globals safe).**
- **`make purs`** fetches a **pinned, SHA-256-checksummed** `purs` tarball into git-ignored **`vendor/purs/`** (npm-12 blocks the `purescript` package's install-script, exactly like it warns on esbuild/wrangler; so the compiler is vendored, mirroring vendored Lit + exact-pinned esbuild). ## Verifying the live site (headless browser)

`make check` (linkcheck) is the only static test. Anything that depends on **client JS actually running** — anchor jumps, pagination-aware scroll-to-comment, board/DM rendering — cannot be verified with curl, only with a real browser. A headless Chromium is preinstalled at `~/.cloakbrowser`: several `chromium-<version>/` dirs, each holding a matching `chrome` and `chromedriver`. There is no node/npm, so drive it through chromedriver's WebDriver HTTP API using Python stdlib only:

- Launch `~/.cloakbrowser/chromium-<ver>/chromedriver --port=N` in the background; poll `GET /status` until ready.
- `POST /session` with `capabilities.alwaysMatch.goog:chromeOptions.binary` set to the sibling `chrome`, args `--headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage --window-size=1200,800 --user-data-dir=<scratchpad>`. Pair `chrome` and `chromedriver` from the **same** version dir or the session refuses to start.
- `POST /session/<id>/url` to navigate (full URL including the `#comment-N` hash), then poll `POST /session/<id>/execute/sync` running a JS probe until the async board fetch has rendered, and read back DOM facts (element presence, `.board-pages strong` = active page, `window.scrollY`, `getBoundingClientRect().top`).
- Always `DELETE /session/<id>` and SIGTERM chromedriver when done.

This catches what curl cannot: e.g. that `community.html?topic=<t>#comment-<id>` resolves to the correct page and scrolls to the comment. (The client sends `&find=<id>` only when there is no explicit `&p`; the worker then counts prior live replies to compute the page. A bare `Math.max(1, …)` default for the page number silently disables this — the page defaults to 1 and the jump strands on page one.)
